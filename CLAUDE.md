# AVITO-PROJECT

**B2B SaaS-коробка для оптовиков одежды.** Single-tenant: один деплой
на одного клиента. Внутри инсталляции — панель владельца, PWA
отправщика, 5 Telegram-ботов (customer / partner / owner / shipper /
director), AI-продажник для Авито-магазинов. Конечные клиенты оптовика
— дропшипперы, перепродают на Авито. Веб-сайта для них нет, всё через
Telegram.

> Репозиторий используется командой: владелец продукта + партнёры,
> задачи распределяются на созвонах. Здесь нет персонального плана/
> roadmap'а; источник истины по бизнес-логике — каноничный документ
> ниже, по техническому состоянию — handoff/smoke-map.

## 🔑 Источник истины

[`docs/BUSINESS_LOGIC.md`](docs/BUSINESS_LOGIC.md) — единственный канон
по бизнес-модели (статусы, возвраты, +ВАЙБ, партнёры, деньги, Касса,
уведомления, anti-replay, auto-resume и т.п.). **Если код расходится с
каноном — приводим код к канону**, не наоборот. Канон поддерживается в
актуальном состоянии между сессиями — позвоночник проекта.

## 👥 Роли в системе

- **Владелец** → `/owner/*` web-панель + DM owner-bot (стратегия,
  финансы, Касса).
- **Директор** (опц.) → DM director-bot (операционка с клиентами,
  гибкий routing 7 типов уведомлений).
- **Отправщик** → `/shipper/*` PWA + DM shipper-bot (push-канал).
- **Клиент** (дропшиппер) → DM customer-bot.
- **Партнёр** (другой оптовик) → DM partner-bot.

## ⚙️ Команды

```bash
npm run dev:all   # Главная: Next.js + worker + 5 ботов в polling
npm run build     # Production-сборка + tsc-проверка
npm run db:push   # Применить миграции на linked Supabase
npm run db:gen-types  # Регенерация TS-типов после миграции
```

## 🧰 Инструменты

- **Supabase**: см. правила и неочевидности в `docs/DATABASE.md`
  (миграции через `npm run db:push`, типы — `db:gen-types`,
  multi-statement лимит пулера, какой клиент когда).
- **Playwright MCP**: реальный Chromium доступен в среде — для
  визуальной проверки UI и SPA-ресёрча.

## 📝 Конвенции

- **Деньги/склад/заказы** — после правки прогонять `tsc` и probe-
  скрипт против реальной БД (`scripts/_tmp-*.ts` с
  `@supabase/supabase-js` + `dotenv .env.local`, не app-client; чистить
  временные скрипты после).
- **Канон-формулы** в коде (`isRevenueCounted`, `ownerRevenue`,
  `ownerCost`, `aggregateOwnerFinance`) — единственный способ считать
  выручку/прибыль на любом экране; не переизобретать.
- **Миграции** нумеровать после последней применённой; одна миграция =
  одна SQL-команда (Supabase pooler limit).
- **Тон UI** — обращение на «ты», единый стиль с тон-каноном ботов
  (см. `bot_texts_tone_canon` если в системе memory).
